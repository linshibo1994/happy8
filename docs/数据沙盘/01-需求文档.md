# 数据沙盘需求文档

## 1. 背景

当前项目已经具备历史开奖、基础统计、走势和前端数据看板雏形。用户希望在此基础上建设一个更强的数据沙盘，围绕快乐8历史开奖进行规则筛选、分区分析、连号/隔号事件检索、事件间隔复盘和规律总结。

本功能需要前后端同时支持：后端负责稳定、可复用、可测试的数据查询和规则计算；前端负责高信息密度的数据分析界面、筛选交互、结果表格、统计摘要和动效表达。

## 2. 产品定位

数据沙盘是“历史开奖数据分析工作台”，不是营销页，也不是确定性预测工具。它要帮助用户回答：

1. 某一期或某段历史开奖是什么。
2. 最近 N 期内出现过哪些连号、隔号和复合结构。
3. 全局和八区内，两连、三连、四连的出现频率和明细是什么。
4. 某类连号事件出现后，下一次再次出现通常间隔多少期。
5. 选择某个连号等级和分析期数后，近期规律是否有可描述的统计特征。

## 3. 用户场景

### 3.1 查看历史开奖

用户进入数据沙盘后，可以查看所有历史开奖记录。每条记录展示期号、开奖日期、20 个开奖号码、和值、奇偶比、大小比、区间分布等基础字段。

### 3.2 按期号查询

用户输入完整期号时，系统返回该期开奖详情；输入部分期号时，系统返回匹配期号列表。查询结果应能继续展示该期的连号、隔号、八区分布等结构标签。

### 3.3 分页浏览

历史开奖列表和规则筛选结果都需要分页。用户可以选择每页条数、上一页、下一页和跳转页码。筛选条件变化后自动回到第一页。

### 3.4 最近 N 期规则筛选

用户选择最近 30、50、100、200、500 或自定义期数后，系统只在该窗口内计算规则结果。例如用户选择最近 100 期和“两连号”，下方展示最近 100 期中存在两连号的期号、开奖号码和连号组。

### 3.5 全局连号筛选

用户可以选择两连号、三连号、四连号。系统在每期开奖的 20 个号码中查找连续号码段，展示命中的期号、开奖日期、完整开奖号码、命中连号组、组数和最长连号长度。

### 3.6 八区连号筛选

用户可以选择八区中的一个或多个区，再选择两连号、三连号或四连号。系统只在所选区间内计算连号，不跨区计算。第一区为 1-10，第二区为 11-20，以此类推到第八区 71-80。

### 3.7 隔号筛选

用户可以筛选隔号事件。默认隔号指同期开奖中存在差值为 2 的号码对，例如 03 和 05、10 和 12。系统展示命中期号、隔号组、所在区和完整开奖号码。

### 3.8 连号隔号筛选

用户可以筛选同时包含连号和隔号的复合结构，例如 `[10,11,13]`、`[10,12,13]`、`[10,11,13,14]`。系统展示复合结构类型、号码组、所在期号和所在区。

### 3.9 下一次出现间隔

用户可以选择一个事件类型，例如“四连号”，查看每次四连号出现后，下一次四连号出现隔了多少期。这个分析也需要支持八区条件，例如“第三区四连号下一次出现间隔”。

### 3.10 连号分析规律总结

用户选择连号等级和分析范围，例如“三连号 + 最近 100 期”，点击分析后，系统生成描述性总结：出现多少期、出现率、平均间隔、最长空窗、最近一次出现、哪些区更集中、是否高于或低于更长周期基线。

## 4. 功能范围

### 4.1 必须支持

1. 历史开奖记录列表。
2. 按期号精确查询和模糊查询。
3. 历史列表分页。
4. 最近 N 期窗口筛选。
5. 全局两连、三连、四连筛选。
6. 八区两连、三连、四连筛选。
7. 全局和八区隔号筛选。
8. 全局和八区连号隔号筛选。
9. 同类事件下一次出现间隔分析。
10. 连号分析规律总结。
11. 筛选结果下方表格展示命中期号、开奖号码和命中结构。
12. 前端页面样式和动效设计，符合数据分析工具气质。

### 4.2 建议支持

1. 当前筛选条件同步到 URL query，便于刷新和分享。
2. 筛选条件一键清空和保存常用视图。
3. 结果导出 CSV。
4. 表格行复制。
5. 点击统计卡联动筛选结果表。
6. 图表导出图片。

### 4.3 暂不纳入本阶段

1. 真实投注建议。
2. 付费策略和会员权益改造。
3. 数据库迁移方案。
4. 具体开发任务拆分。
5. 预测算法调整。

## 5. 前端需求

1. 页面应以“数据沙盘”为核心操作台，首屏直接展示筛选器、摘要指标、分析面板和结果表，不做营销式首屏。
2. 筛选器包括分析期数、期号、日期范围、事件类型、连号等级、区间、分页参数。
3. 结果区域支持历史开奖表、规则命中表、间隔分析表和规律总结面板。
4. 使用紧凑但清晰的视觉风格：表格、图表、指标条和筛选器优先，减少装饰。
5. 动效用于表达加载、筛选刷新、命中高亮和图表更新，不做循环闪烁。
6. 移动端需要提供筛选抽屉和表格横向查看能力。

## 6. 后端需求

1. 提供历史开奖分页接口，返回真实总数。
2. 提供期号查询接口。
3. 提供数据沙盘规则分析接口，支持最近 N 期、日期范围、期号、区间、事件类型和连号等级。
4. 提供事件间隔分析接口，支持全局和八区口径。
5. 提供规律总结接口或后端可复用的总结数据结构，前端可基于模板展示。
6. 规则计算应放在服务层或独立分析模块，不放在路由函数中。
7. 所有规则计算需要单元测试覆盖典型样例和边界样例。

## 8. 待确认问题

1. 四连号是否在“两连号筛选”中也算命中。建议：筛选按“至少 N 连”命中，展示按最长连续段标注。
2. 连号组数是否展开重叠子组。建议：默认展示最大连续段，提供“展开子组”作为高级选项。
3. 全局连号是否允许跨八区边界。建议：全局允许跨区，八区模式不允许跨区。
4. 隔号是否只指差值为 2。建议：本阶段固定为差值为 2。
5. 连号隔号具体支持哪些结构。建议：号码组相邻差值只包含 1 和 2，且同时存在 1 和 2。
6. “隔多少期”按中间空窗期数还是期号步长。建议：主显示空窗期数，辅助显示相邻事件距离。
7. 日期范围和最近 N 期同时选择时谁优先。建议：先按日期/期号过滤，再取最近 N 期作为分析窗口。
8. 规律总结是否输出预测建议。建议：只输出描述性统计和风险提示，不输出确定性预测。
