# 数据沙盘验收边界

## 1. 功能验收

1. 用户可以在数据沙盘页面查看历史开奖记录。
2. 用户可以按期号查询开奖记录。
3. 历史开奖和规则结果支持分页。
4. 用户可以选择最近 N 期作为分析窗口。
5. 用户可以筛选全局两连、三连、四连。
6. 用户可以筛选八区两连、三连、四连。
7. 用户可以筛选隔号事件。
8. 用户可以筛选连号隔号复合事件。
9. 用户可以查看某类事件下一次出现间隔。
10. 用户可以生成连号分析规律总结。
11. 用户可以触发外部联网查询，且失败时页面不崩溃。

## 2. 规则验收

| 样例 | 预期 |
| --- | --- |
| `[1,2]` | 命中全局两连 |
| `[10,11,12,13]` | 命中全局四连，并能命中两连/三连筛选 |
| `[9,10,11]` | 全局命中三连，八区仅一区命中两连 |
| `[21,22,23]` | 命中三区三连 |
| `[1,3]` | 命中隔号 |
| `[10,11,13]` | 命中连号隔号 |
| 事件出现 1 次 | 间隔统计显示样本不足 |
| 100 期和 103 期出现同类事件 | 空窗期数为 2，相邻事件距离为 3 |

## 3. 页面验收

1. 页面首屏是数据工具界面，不是营销页。
2. 筛选器、摘要指标、分析面板和结果表可见。
3. 命中号码有清晰高亮，非命中号码仍可读。
4. 加载、空、错误、样本不足状态都有明确中文文案。
5. 移动端或窄屏下不出现文本严重溢出和控件重叠。
6. 动效短促、服务于状态变化，不循环闪烁。

## 4. 后端验收

1. 规则计算在服务层完成。
2. `/lottery/history` 返回筛选后真实 `total`。
3. 数据沙盘接口参数有上限和校验。
4. 外部联网查询有超时、异常捕获和降级结果。
5. 单元测试覆盖核心规则和边界。

## 5. 验证命令

后端：

```bash
cd backend
pytest -q
```

前端：

```bash
cd frontend
npm run test:unit -- --run
npm run build
```

页面：

```bash
cd frontend
npm run dev -- --host 127.0.0.1
```

然后用浏览器打开 `http://127.0.0.1:5173/data` 做真实页面验证。

## 6. 不通过条件

1. 任一核心规则计算与已确认口径不一致。
2. 外网失败导致页面无法加载本地历史数据。
3. 页面出现明显重叠、空白或控制台关键错误。
4. 测试未运行且没有明确说明原因。
5. 提交混入 `.codex/` 或其他无关改动。
