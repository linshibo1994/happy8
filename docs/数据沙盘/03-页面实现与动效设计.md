# 页面实现与动效设计

## 1. 设计定位

数据沙盘页面应表现为面向高频数据分析用户的工作台：安静、清晰、密集、可扫描。页面不做营销式首屏，不使用大幅宣传图，不用过度红金配色，不用循环闪烁动效。

现有 `frontend/src/pages/DataDashboardPage.vue` 已有筛选器、指标卡、ECharts 图表、表格模式和密度切换，数据沙盘应在此基础上扩展，而不是另起一套不一致的设计语言。

## 2. 页面信息架构

### 2.1 顶部状态区

顶部展示：

1. 页面标题：数据沙盘。
2. 当前数据最新期号。
3. 最近同步时间。
4. 当前分析窗口，例如“最近 100 期，实际统计 100 期”。
5. 操作按钮：刷新、重置、导出、密度切换。

按钮建议使用 lucide 图标，配合 tooltip 和 `aria-label`。不要使用大面积文字按钮堆叠。

### 2.2 固定筛选工具栏

筛选工具栏在桌面端固定在内容顶部，横向紧凑排列：

| 筛选器 | 控件建议 |
| --- | --- |
| 分析期数 | 分段控件：30、50、100、200、500、自定义 |
| 期号 | 搜索输入框，支持精确和模糊 |
| 日期范围 | 日期范围选择器 |
| 事件类型 | Tabs 或分段控件：连号、隔号、连号隔号、间隔 |
| 连号等级 | 分段控件：两连、三连、四连 |
| 分析口径 | Segmented：全局、八区 |
| 八区选择 | 8 个紧凑复选按钮 |
| 分页大小 | 下拉选择：20、50、100 |

筛选条件变化后，不应整页跳动，只刷新摘要、图表和结果表。筛选条件应同步到 URL query，便于刷新后保留现场。

### 2.3 摘要指标条

摘要区使用紧凑指标条，不做大型卡片堆叠。

建议指标：

1. 开奖期数。
2. 命中期数。
3. 命中率。
4. 总组数。
5. 平均空窗。
6. 当前遗漏。
7. 高频区。
8. 最近命中期号。

数字、期号、百分比使用等宽字体，便于横向比较。

### 2.4 主分析区

桌面端采用 12 栅格布局：

1. 左侧 8 栅格：八区热力图、事件时间线、间隔柱状图、号码结构分布。
2. 右侧 4 栅格：规律总结、当前筛选解读、异常状态提醒。

每个分析面板保持固定结构：

```text
标题 + 当前口径标签
一句摘要
图表或表格
导出/展开/复制操作
```

### 2.5 结果表区

结果表是页面核心区域之一，需要支持四种模式：

| 模式 | 用途 |
| --- | --- |
| 历史开奖表 | 查看全部或筛选后的开奖历史 |
| 规则命中表 | 展示连号、隔号、连号隔号命中期号 |
| 间隔分析表 | 展示事件序列和下一次出现间隔 |
| 号码统计表 | 展示号码频率、遗漏、所在区等基础统计 |

表格要求：

1. 表头 sticky。
2. 横向滚动时有边缘阴影提示。
3. 行 hover 只做轻微背景变化。
4. 命中号码球高亮，非命中号码降低对比度但仍可读。
5. 支持复制行数据。
6. 支持排序状态显示。
7. 分页控件放在表格底部，展示当前页、总页数、总记录数。

### 2.6 规律总结区

规律总结区展示模板化分析，不做确定预测。

展示结构：

1. 分析口径：例如“最近 100 期，全局三连号”。
2. 样本提示：例如“实际统计 100 期”。
3. 关键结论：出现率、平均空窗、最长空窗、当前遗漏。
4. 八区偏态：哪些区更集中。
5. 风险提示：历史统计只描述样本，不代表未来确定结果。
6. 证据入口：点击跳转到命中期号表和间隔表。

## 3. 视觉风格

### 3.1 色彩

沿用现有前端 token 方向：

| 用途 | 建议颜色 |
| --- | --- |
| 关键命中、强调 | 朱砂红 |
| 选中、链接、执行 | 数据蓝 |
| 成功、同步完成 | 松石绿 |
| 风险、异常、长遗漏 | 风险橙 |
| 背景 | 玉白/白色 |
| 边框 | 低对比灰线 |

避免大面积红金、紫蓝渐变、深色大屏风和装饰性光效。

### 3.2 组件形态

1. 面板圆角不超过 8px。
2. 表格和筛选器优先使用边框和留白区分层级。
3. 不把页面区块做成一层套一层的卡片。
4. 号码球尺寸保持稳定，避免筛选高亮导致行高变化。
5. 复杂图表使用固定高度和响应式宽度，避免加载后布局跳动。

### 3.3 字体与排版

1. 标题使用克制字号，不使用 hero 级大标题。
2. 表格单元格和筛选控件以 12-14px 为主。
3. 期号、号码、百分比、间隔期数使用等宽数字。
4. 不使用负字距，不用随 viewport 缩放的字体。

## 4. 动效设计

### 4.1 页面进入

页面进入时采用短递进：

1. 筛选栏先出现。
2. 摘要指标条随后出现。
3. 图表面板出现。
4. 结果表出现。

每段间隔控制在 60ms 左右，整体不超过 300ms。

### 4.2 筛选刷新

筛选条件变化后：

1. 摘要数字使用 140-180ms 的数值淡入。
2. 图表使用 160-220ms 的淡入更新。
3. 表格行使用透明度过渡。
4. 不改变控件高度，避免页面抖动。

### 4.3 命中高亮

1. 命中号码球使用一次轻微高亮。
2. 命中连号组可用细边框连起来，或用同色标签表达。
3. 不使用循环闪烁。
4. 用户 hover 某个命中组时，对应号码球同步高亮。

### 4.4 同步与加载

1. 首次加载：摘要区骨架屏，表格保留表头骨架。
2. 局部刷新：只在相关面板显示轻量 loading。
3. 同步最新开奖：刷新按钮旋转一次，完成后显示更新时间。
4. 接口失败：失败面板保留重试按钮和最近成功更新时间。

### 4.5 减少动效偏好

必须尊重 `prefers-reduced-motion`：

1. 关闭非必要过渡。
2. 保留状态文案。
3. 保留加载进度和错误提示。

## 5. 移动端适配

移动端采用单列布局：

1. 筛选器收进顶部折叠面板或底部抽屉。
2. 摘要指标改为 2 列紧凑网格。
3. 图表默认显示关键摘要，复杂图表提供全屏展开。
4. 表格提供“卡片摘要行”和“横向全表查看”两种模式。
5. 分页控件简化为上一页、下一页、页码状态和每页条数。

移动端不能把 20 个号码挤压到不可读状态。号码球可换行，但行高必须稳定。

## 6. 可访问性

1. 图表提供中文 `aria-label`。
2. 号码球不能只靠颜色区分命中状态，需要有文本或 `aria-label`。
3. 表格排序按钮提供当前排序方向。
4. 图标按钮提供 tooltip 和 `aria-label`。
5. 筛选器必须有 label，不只依赖 placeholder。
6. 键盘焦点态沿用全局 focus ring。
7. 灰字、橙色警告、青铜色标签在浅色背景上需要满足可读对比。

## 7. 状态文案

| 状态 | 建议文案 |
| --- | --- |
| 加载中 | 正在读取历史开奖数据 |
| 规则计算中 | 正在分析当前筛选规则 |
| 无历史数据 | 当前筛选范围暂无开奖记录 |
| 无命中事件 | 当前条件下未找到命中期号 |
| 样本不足 | 当前事件出现次数不足，无法计算间隔 |
| 接口失败 | 数据获取失败，请稍后重试 |
| 同步失败 | 最新开奖同步失败，已保留最近成功数据 |
| 权限不足 | 当前分析视图暂无访问权限 |

## 8. 前端组件建议

后续开发可拆分组件：

| 组件 | 职责 |
| --- | --- |
| `SandboxFilterBar.vue` | 分析期数、期号、事件类型、八区等筛选 |
| `SandboxMetricStrip.vue` | 命中期数、命中率、间隔等摘要 |
| `SandboxEventTable.vue` | 规则命中结果表 |
| `SandboxIntervalTable.vue` | 事件间隔表 |
| `ZonePatternHeatmap.vue` | 八区连号热力图 |
| `PatternSummaryPanel.vue` | 连号规律总结 |

组件命名只是设计建议，最终应结合现有前端结构确定。
