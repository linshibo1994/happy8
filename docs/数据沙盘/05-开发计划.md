# 数据沙盘开发计划

## 1. 已确认口径

1. 八区固定为每 10 个号码一区：1-10、11-20、...、71-80。
2. 连号筛选按“至少 N 连”命中：四连会命中两连和三连筛选。
3. 连号展示默认按最大连续段计数，不展开重叠子组。
4. 全局连号允许跨八区边界，八区连号不跨区。
5. 隔号固定为差值 2 的号码对。
6. 连号隔号采用“同组差值只包含 1 和 2，且两者都出现”的定义。
7. “隔多少期”主指标为空窗期数，辅助指标为相邻事件距离。
8. 日期范围和最近 N 期同时存在时，先过滤再取最近 N 期。
9. 连号规律总结只做描述性统计，不输出确定性预测。
10. 外部联网查询需要实现，但必须支持失败降级，不影响本地历史数据分析。

## 2. 实施原则

1. 后端规则计算放在服务层，路由只做参数解析和响应封装。
2. 前端优先复用现有 `DataDashboardPage.vue`、图表组件、号码球和样式 token。
3. 不重构会员、预测算法、支付、数据库迁移和 CI。
4. 外部联网查询只做只读公开数据抓取或官方入口探测，失败时返回明确状态。
5. 每一步实现后都要通过测试和人工页面验证闭环。

## 3. 后端任务

### 3.1 历史数据分页增强

1. 增强 `LotteryService.get_historical_results`，返回数据列表和筛选后真实总数。
2. 保持 `/lottery/history` 响应兼容，新增 `limit`、`offset` 语义下的真实 `total`。
3. 查询条件包含日期范围和期号模糊匹配。

### 3.2 数据沙盘规则服务

新增或扩展服务层，提供：

1. 最近 N 期窗口选择。
2. 全局/八区连号识别。
3. 全局/八区隔号识别。
4. 全局/八区连号隔号识别。
5. 规则命中结果分页。
6. 八区统计摘要。

### 3.3 间隔分析

1. 根据事件类型生成出现期号序列。
2. 计算空窗期数、相邻事件距离、平均空窗、中位空窗、最大空窗、当前遗漏。
3. 事件出现少于 2 次时返回样本不足状态。

### 3.4 规律总结

1. 根据连号等级、范围和口径生成结构化统计。
2. 输出模板化中文摘要。
3. 文案只描述历史样本，不做预测承诺。

### 3.5 外部联网查询

1. 提供一个数据沙盘外部查询接口，用于页面触发“联网查询/刷新”。
2. 优先调用现有同步能力或公开开奖接口；外网失败时返回失败原因和本地最近数据状态。
3. 不让外网异常影响规则筛选、历史分页和页面加载。

## 4. 前端任务

### 4.1 API 与类型

1. 增加数据沙盘请求和响应类型。
2. 增加规则筛选、间隔分析、规律总结、联网查询 API 方法。
3. 保持现有最新开奖 API 不破坏。

### 4.2 页面筛选区

1. 增加分析期数、期号、事件类型、连号等级、全局/八区、区号、分页大小。
2. 筛选条件变化后刷新摘要和表格。
3. 关键筛选条件同步到 URL query。

### 4.3 结果与分析区

1. 历史开奖分页表。
2. 规则命中结果表。
3. 间隔分析表和指标条。
4. 连号规律总结面板。
5. 八区热力或紧凑分布面板。
6. 外部联网查询状态提示。

### 4.4 样式与动效

1. 继续使用现有 token，不做营销页。
2. 筛选刷新、表格更新、命中号码高亮使用短过渡。
3. 支持加载、空、错误、样本不足状态。
4. 移动端筛选器可折叠，表格可横向滚动。

## 5. 测试计划

### 5.1 后端测试

1. 单元测试连号、隔号、连号隔号识别。
2. 测试八区跨界不误算。
3. 测试间隔样本不足和正常间隔。
4. 测试历史分页真实 total。
5. 测试外部查询失败降级。

### 5.2 前端测试

1. 单元测试页面能渲染数据沙盘入口和核心筛选器。
2. 测试 API mock 下的规则命中表和总结面板。
3. 测试类型检查和生产构建。

### 5.3 真实页面测试

1. 启动前端开发服务。
2. 用浏览器打开数据沙盘页面。
3. 验证筛选器、规则结果、间隔分析、规律总结和联网查询状态可见。
4. 截图或 DOM 状态确认页面没有明显重叠、空白和错误。

## 6. Review 计划

完成开发后执行一次代码 review 自检：

1. 查看 `git diff --stat` 和 `git diff`。
2. 检查是否混入 `.codex/` 或其他无关改动。
3. 检查敏感信息、外部 URL、异常处理和失败降级。
4. 检查规则口径是否与文档一致。
5. 检查测试是否覆盖关键边界。

## 7. 提交与推送

1. 只暂存本次相关文件。
2. 使用中文提交信息。
3. 提交后推送到当前远程分支。
4. 若推送失败，报告失败原因和后续处理建议。
