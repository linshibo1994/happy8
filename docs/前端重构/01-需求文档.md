# 前端重构需求文档

## 1. 产品定位

Happy8 新前端定位为“快乐8数据预测与复盘工作台”。它不是单纯的选号页面，而是帮助用户完成以下闭环：

看最新开奖 -> 观察走势 -> 选择算法 -> 执行预测 -> 对比结果 -> 复盘命中 -> 调整下一次策略。

## 2. 目标用户

| 用户类型 | 典型行为 | 设计重点 |
| --- | --- | --- |
| 高频彩民 | 每天查看开奖、走势、遗漏、冷热号 | 首屏效率、快速预测、历史复盘 |
| 数据型用户 | 关注频率、区间、奇偶、和值、算法表现 | 看板、表格、筛选、导出 |
| 算法尝试者 | 喜欢比较不同算法结果 | 批量预测、多算法对比、置信度解释 |
| 会员用户 | 关注可用算法、次数、权益和订单 | 权限提示、会员状态、升级路径 |
| 管理用户 | 需要同步开奖、检查算法状态 | 诊断、同步、系统状态 |

## 3. 核心页面范围

| 页面 | 必须能力 |
| --- | --- |
| 首页工作台 | 最新开奖、下期期号、快捷预测、今日次数、近期命中、热门算法 |
| 预测执行页 | 单算法预测、批量预测、参数设置、阶段进度、实时结果 |
| 算法中心 | 17种核心算法列表、权限等级、复杂度、历史表现、详情页 |
| 历史数据看板 | 开奖历史、走势图、频率、冷热、遗漏、区间、和值、奇偶大小 |
| 预测历史 | 预测记录、命中复盘、算法筛选、期号筛选、结果对比 |
| 会员中心 | 当前等级、剩余次数、套餐权益、订单状态 |
| 个人中心 | 用户资料、统计、偏好设置、通知设置 |
| 系统诊断 | 数据同步、算法诊断、接口状态，仅管理员可见 |

## 4. 核心功能需求

### 4.1 开奖与走势

- 展示最新一期开奖号码，包含期号、开奖时间、20个号码、和值、奇偶比、大小比、区间分布。
- 支持按期号、日期、号码组合筛选历史开奖。
- 支持走势图视图：号码出现、遗漏、热度、区间分布、和值走势。
- 支持表格视图：可排序、筛选、固定列、密度切换。

### 4.2 预测执行

- 支持单算法预测：选择算法、目标期号、分析期数、预测个数、算法参数。
- 支持批量预测：一次选择多个算法并行执行。
- 执行过程必须有阶段进度，不允许只显示一个静态 loading。
- 预测完成后展示预测号码、置信度、耗时、是否缓存、算法参数、分析说明。
- 预测结果可进入历史记录，待开奖后自动显示命中情况。

### 4.3 算法中心

后端当前支持的算法白名单包括：

| 分类 | 算法 |
| --- | --- |
| 基础统计 | `frequency`、`hot_cold`、`missing` |
| 马尔可夫 | `markov`、`markov_basic`、`markov_2nd`、`markov_3rd`、`adaptive_markov` |
| 机器学习 | `ensemble`、`ensemble_basic`、`ml_ensemble`、`advanced_ensemble`、`clustering`、`monte_carlo` |
| 深度学习 | `deep_learning`、`lstm`、`transformer`、`gnn` |
| 概率与综合 | `bayesian`、`high_confidence`、`super_predictor` |

说明：算法配置中核心算法为17种，接口白名单同时保留部分兼容别名。前端应按核心算法展示，兼容别名只用于接口调用或历史数据回显。

### 4.4 用户与会员

- 未登录用户可以查看开奖、走势和基础介绍，但执行预测需要登录。
- 免费用户展示每日次数上限和剩余次数。
- VIP/Premium 算法在卡片上展示锁定态、权益说明和升级入口。
- 支付相关页面必须强调订单状态、金额、套餐、有效期。

## 5. 非功能需求

- 首屏关键内容 2 秒内可见。
- 表格 1000 行以内操作不卡顿。
- 预测执行页必须防重复提交。
- 所有接口错误必须有可理解提示，不允许只展示技术错误。
- 移动端、平板、桌面端均可使用。
- 所有涉及预测的页面必须展示概率性免责声明，文案简短克制。

## 6. 不做范围

- 不承诺彩票结果确定性。
- 不设计夸张营销页。
- 不把会员购买放在预测结果之前强打断。
- 不使用与业务无关的装饰动画。
