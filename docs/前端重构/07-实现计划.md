# 前端重构实现计划

## 阶段 0：准备

目标：建立新前端工程，不接业务。

任务：

- 初始化 `frontend/` 工程。
- 接入 Vue 3、TypeScript、Vite、Pinia、Vue Router。
- 接入 Naive UI、ECharts、lucide、GSAP。
- 建立主题 token、布局系统、基础组件。

验收：

- 本地开发服务可启动。
- 首页空壳、路由、主题切换可运行。
- CI 能执行 lint、type-check、unit test。

## 阶段 1：基础框架

目标：形成可导航的应用骨架。

任务：

- 实现 AppShell。
- 实现桌面侧边导航和移动底部导航。
- 实现登录态、会员态、全局错误提示。
- 实现 API Client 和请求拦截。

验收：

- 所有一级页面可访问。
- 未登录、登录、权限不足状态可区分。
- 接口错误有统一提示。

## 阶段 2：数据看板

目标：完成开奖数据与历史走势能力。

任务：

- 接入最新开奖。
- 实现历史开奖表。
- 实现频率、冷热、遗漏、区间、和值图表。
- 实现筛选联动。

验收：

- 筛选条件能驱动图表和表格。
- 1000行以内表格操作流畅。
- 图表有加载、空、错误状态。

## 阶段 3：预测执行

目标：完成核心预测闭环。

任务：

- 实现算法选择。
- 实现单算法预测。
- 实现批量预测。
- 实现阶段进度条和算法专属动效。
- 实现预测结果详情。

验收：

- 所有算法可展示。
- 可用算法能执行。
- 不可用算法有锁定说明。
- 结果能进入历史并可复盘。

## 阶段 4：算法中心与会员

目标：完善算法理解和权益链路。

任务：

- 实现算法中心。
- 实现算法详情。
- 实现会员中心、套餐、订单。
- 实现支付状态页面。

验收：

- 权限等级展示准确。
- 升级路径不打断基础浏览。
- 订单状态清晰。

## 阶段 5：质量强化

目标：达到可上线质量。

任务：

- E2E 覆盖核心路径。
- 移动端适配。
- 性能优化。
- 可访问性检查。
- 视觉走查。

验收：

- 首页、预测页、看板页移动端和桌面端均无明显错位。
- 首屏关键内容 2 秒内可见。
- 预测执行无重复提交问题。

## 建议开发顺序

1. 工程骨架。
2. API Client 和类型定义。
3. 号码球、指标卡、表格、图表基础组件。
4. 首页工作台。
5. 历史数据看板。
6. 预测执行页。
7. 算法中心。
8. 会员与订单。
9. 测试、性能和视觉精修。

## 主要风险

| 风险 | 处理 |
| --- | --- |
| 后端接口字段不稳定 | 前端通过类型层和 adapter 兼容 |
| 图表数据量大 | 分页、采样、虚拟滚动 |
| 动效影响性能 | 限制动效数量，优先 CSS transform |
| 算法执行无真实进度 | 采用阶段式进度，不伪造细粒度后端状态 |
| 支付链路敏感 | 独立安全 Review |
