# 前端技术方案

## 1. 推荐技术栈

| 层级 | 技术 | 理由 |
| --- | --- | --- |
| 构建 | Vite | 快速、成熟、适合 Vue 生态 |
| 框架 | Vue 3 + TypeScript | 与历史项目技术方向一致，类型约束清晰 |
| 路由 | Vue Router | 标准路由能力 |
| 状态 | Pinia | 用户、会员、预测参数等全局状态 |
| 请求 | Axios + TanStack Query for Vue | 接口缓存、重试、失效更新更清晰 |
| 组件库 | Naive UI | 表格、表单、弹窗、暗色适配成熟 |
| 图表 | Apache ECharts | 走势、热力、区间、频率图能力强 |
| 动效 | GSAP + VueUse Motion | 阶段进度、号码生成、页面过渡 |
| 图标 | lucide-vue-next | 图标体系简洁统一 |
| 样式 | SCSS + CSS Variables | 主题 token 可维护 |
| 测试 | Vitest + Playwright | 单元测试与关键路径 E2E |

## 2. 组件库选择

推荐主组件库：`Naive UI`。

原因：

- `DataTable` 能满足历史开奖、预测历史、算法统计表。
- `Form`、`Slider`、`InputNumber` 适合预测参数配置。
- `Tabs`、`Drawer`、`Modal` 适合移动端与详情页。
- 主题定制能力强，可以落地朱砂、深墨、玉白体系。

补充组件：

- `ECharts`：全部数据图表。
- `lucide-vue-next`：导航、操作、状态图标。
- `GSAP`：复杂执行进度与数字生成动效。

## 4. API 对接

现有后端 API 前缀为 `/api/v1`。

| 模块 | 关键接口 |
| --- | --- |
| 预测 | `GET /predictions/algorithms`、`POST /predictions/predict`、`POST /predictions/batch-predict` |
| 预测历史 | `GET /predictions/history`、`GET /predictions/stats` |
| 开奖 | `GET /lottery/latest`、`GET /lottery/history`、`GET /lottery/statistics`、`GET /lottery/trends`、`GET /lottery/search` |
| 算法 | `GET /algorithms/`、`GET /algorithms/{algorithm_name}`、`GET /algorithms/{algorithm_name}/stats` |
| 会员 | `GET /memberships/status`、`GET /memberships/plans`、`GET /memberships/orders` |
| 支付 | `GET /payments/methods`、`POST /payments/create`、`GET /payments/status/{order_no}` |
| 用户 | `GET /users/profile`、`PUT /users/profile`、`POST /auth/wechat-login` |

## 5. 状态管理

| Store | 状态 |
| --- | --- |
| `useUserStore` | token、用户资料、登录状态 |
| `useMembershipStore` | 等级、剩余次数、套餐、订单 |
| `useLotteryStore` | 最新开奖、历史开奖、走势图筛选 |
| `usePredictionStore` | 当前参数、执行状态、结果、历史 |
| `useAlgorithmStore` | 算法列表、算法详情、算法统计 |
| `useUiStore` | 主题、布局密度、抽屉、全局消息 |

## 6. 预测执行状态模型

```ts
type PredictionPhase =
  | 'permission'
  | 'data'
  | 'feature'
  | 'compute'
  | 'validate'
  | 'done'
  | 'error'

interface PredictionExecutionState {
  id: string
  algorithm: string
  targetIssue: string
  progress: number
  phase: PredictionPhase
  message: string
  startedAt: number
  endedAt?: number
  result?: PredictionResult
  error?: string
}
```

## 7. 性能策略

- 开奖历史表格开启分页和虚拟滚动。
- 图表数据按筛选条件缓存。
- 预测按钮防抖，执行期间禁用重复提交。
- 批量预测使用并发结果逐个落位，不等待全部完成才展示。
- 大图表在移动端默认折叠为摘要卡。

## 8. 安全与合规

- Token 存储必须可控，优先使用安全 cookie 或短期本地存储策略。
- 所有预测页展示概率性提示。
- 支付页不得在前端保存敏感支付参数。
- 管理员接口必须隐藏入口并校验权限。
