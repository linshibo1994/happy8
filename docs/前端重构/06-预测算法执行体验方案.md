# 预测算法执行体验方案

## 1. 设计目标

预测执行页必须让用户明确知道：

- 当前预测的是哪一期。
- 使用的是哪个算法。
- 分析了多少期历史数据。
- 预测了几个号码。
- 执行到了哪个阶段。
- 结果为什么可信或不可信。

## 2. 算法分组展示

| 分组 | 算法 | 页面表现 |
| --- | --- | --- |
| 基础统计 | 频率分析、冷热分析、遗漏分析 | 免费、快速、适合入门 |
| 马尔可夫链 | 基础、二阶、三阶、自适应 | 展示状态转移阶段 |
| 机器学习 | 集成学习、高级集成、聚类、蒙特卡洛 | 展示采样、聚类、模型融合 |
| 深度学习 | LSTM、Transformer、GNN | 展示序列建模、注意力、图关系 |
| 高级综合 | 贝叶斯、高置信度、超级预测器 | 展示概率推理、置信过滤、融合权重 |

## 3. 单算法执行页面

### 参数区

- 目标期号：默认使用最新期开奖的下一期。
- 分析期数：10-200，可用滑块和输入框双控。
- 预测个数：1-20。
- 高级参数：默认折叠，按算法显示。
- 会员权限：不可用算法显示锁定态。

### 执行区

执行中展示：

- 算法名称。
- 当前阶段。
- 总进度。
- 阶段耗时。
- 可取消按钮。
- 执行日志摘要。

### 结果区

结果展示：

- 预测号码球。
- 置信度。
- 执行耗时。
- 是否命中缓存。
- 分析数据摘要。
- 复制号码、保存、查看详情、加入对比。

## 5. 批量预测体验

### 页面结构

```text
顶部：目标期号、分析期数、预测个数、剩余次数
左侧：算法多选列表
中间：批量执行进度矩阵
右侧：交集号码、高频候选、算法分歧
底部：结果表格
```

### 结果分析

| 指标 | 说明 |
| --- | --- |
| 交集号码 | 多个算法同时推荐的号码 |
| 高频候选 | 在预测结果中出现次数最多的号码 |
| 算法分歧 | 各算法差异较大的号码区间 |
| 平均置信度 | 所有成功算法的平均置信度 |
| 最快算法 | 执行耗时最短 |
| 稳定算法 | 历史命中表现更稳定 |

## 6. 进度条细节

前端不能伪装后端真实进度，但可以用“阶段式进度”表达执行流程。

| 阶段 | 前端行为 |
| --- | --- |
| 0-10% | 发起请求、禁用按钮、检查参数 |
| 10-25% | 展示数据准备动画 |
| 25-50% | 展示算法专属分析动画 |
| 50-80% | 等待接口返回，保持阶段动效 |
| 80-95% | 接口返回后处理结果 |
| 95-100% | 号码球定格、展示结果 |

如果接口提前返回，进度条快速补齐到 100%。如果接口超时，停在当前阶段并显示重试。

## 7. 错误处理

| 错误 | 前端处理 |
| --- | --- |
| 权限不足 | 展示锁定说明和升级入口 |
| 次数不足 | 展示剩余次数和会员入口 |
| 算法不可用 | 禁用算法并显示诊断提示 |
| 数据不足 | 提示减少分析期数或同步开奖 |
| 网络失败 | 保留参数，提供重试 |
| 后端超时 | 展示超时状态，不清空用户输入 |

## 8. 预测结果免责声明

建议固定文案：

> 预测结果仅基于历史数据和算法模型生成，不代表确定开奖结果，请理性使用。

文案放在预测结果区底部，字号小但可读。
